some tips intervention

sorry the interruption, i am not the tutor but a longtime user of R and just wanted to prevent the kommilitones not ever been using R when trying to follow whats described in the R-introduction of the 2015! textbook (Levshina (2015)) to give up desperately.

you will stumble across a tiny mentioning of RStudio which you “could also use” instead of the focused on R GUI and CLI. this is not the case. you should instead of trying to gpt-find-out about using the R GUI and such right from the beginning use RStudio to have the appropriate fun-with-R since it is as stated a powerful and easy to use framework/tool/programming language for statistical analyses, corpus-, text-, databaseprocessing up to building complex web or pdf presentations of your work. that is a fact.

RStudio may have been in 2015 not very available yet but since is the IDE (a programming interface to your desktop) that easily allows for package managing, editing and running code, creating and saving your plot graphics and most important to keeping track of the variables created within an R session (which are all the assignments or environment specific processes you will be working with when coding and running code.) if you’re not been coding yet believe me in that, you will be glad to have an accessible overview of that important “variables” and to have a convenient frontend for managing files, datasets, plot outputs and with an integrated helper page on every command which is important for learning instead of copy-paste everything from gpt.

okay…, that was my tip in the beginning…, just add some for the start with RStudio (or also Positron which is kind of succeeding RStudio right now…)

tech preliminary

for installing simply follow the instructions at

  • https://positron.posit.co/download.html for Positron

and/or

  • https://docs.posit.co/ide/user/ide/get-started/ for RStudio.

which are linked under open source when you as advised visit rstudio.com (you will be redirected to the posit which is now the maintainer of RStudio)

  • read carefully and mind you have to install R first which is all described/linked in detail at the top of the page under Hello RStudio but texted bit to overread…
  • RStudio is better for keeping track of environment variables created during an R session, for more advanced plot output and saving, easier managing packages and such but has an aweful files navigator; Positron is good when you are used to navigating your files in a shoebox view which is very convenient but is bit limited in the original R sense and is primarily a good editor.

if you should not have access to a device with a recent OS, its still ways to get either RStudio running despite (i can help you with that at least for MacOS down to Monterey (12) and linux, windows not sure…) or

if you should have only access to a tablet or a real vintage device you should still be able to use RStudio in a webbrowser. for that visit: https://posit.cloud where you have to create an account and then can use a complete RStudio environment in the browser. best for that case would be to create a https://github.com account before and then login with that github account to posit.cloud since then you are able to conveniently access, edit and sync your working files between cloud and desktop. (also works without github account, but just for convenience…) / a github account is also nice since you will as student when having applied for the education program have access to many useful learning ressources, tools and the github copilot which is a better AI coding assistant than gpt and fully integrates into e.g. the Positron IDE if you decide to using that instead of RStudio.

native

and for the first R experience away from the terminal or R GUI which will automatically lead to scripts that you can edit/save and run line-wise instead of hassling with an R history file, try:

  • menu: create file > R script
  • insert command like
3+4*2
[1] 11

or any from the book, and then, an important missing:

  • simply press CMD-enter (mac) or CTRL-enter (windows, linux) with the cursor being somewhere in or at the end of the line in the editor (or anywhere else within a function) and you get your first computation or anything you commanded in that line. sure on an error you get an error :) but theres no line termination necessary or correct indendation of lines like in python. that can mean less errors but also may lead to scribbling instead coding.

  • you can simply comment out a line with the raute like

# commented out (runs not)
print("this command runs and prints this message to standard-out...")
[1] "this command runs and prints this message to standard-out..."
# or calculations as well:
print(3+4*2)
[1] 11
  • that way can create a complex script and run it completely (menu: code > run > from the beginning) with simply commenting out not wanted commands within.
